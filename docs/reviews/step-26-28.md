## Summary

The three steps are mostly faithful to the spec and the boards, and the code is careful about
the project rules:

- **Splash (F-06):** inline SVG and CSS in `index.html`, painted before the bundle; the version is
  put in by a Vite `transformIndexHtml`; `backgroundColor` matches the light `--bg`. The splash is
  always removed: `renderStartup` hides it in a `finally`, and `init().finally` hides it on every
  other path (folder choice, migration, start-up error, a throw). Reduced motion removes it at
  once.
- **Login (V-04):** the stages, stagger, FLIP flight and its reverse, inline PIN with one or two
  fields (168 px reserved), keyboard flow (Enter on tile and badge, Escape back out) and the
  reduced-motion fade are as in spec 4.2 and are covered by `login.spec.ts`. While a user is
  chosen, `.login-pin` (`inset: 0`, later in the DOM) covers the badges and tiles, so a mouse
  double click or a click on a second badge cannot start a second flight. The PIN rules are still
  in Rust; the old dialog flow (`pinLogin`) is fully removed and the recovery dialog's button no
  longer clashes with `#pin-ok`.
- **Photo crop (F-19):** pure geometry in `domain/crop.ts` (tested), positions through the CSSOM
  (CSP holds), JPEG of at most 512 px. `saveOwnPhoto` merges into the file on disk, so an admin's
  change made meanwhile is kept, and an admin who has the user open gets the usual rev conflict.
  D28 is closed: the id is made once and both the file and the photo use it.
- **Cards (F-07, F-08, F-09):** the numbers come only from the core wrappers (`yearAverage`,
  `seAverage`, `trend`, `statsOfAverages`); no grade rule is reimplemented in the UI. Trend levels
  and labels match spec 2.4, grades use the decimal comma, colours go through data attributes,
  the admin keeps the plain student list, and the fixed 66 px card height means no layout shift
  when the grades come in.
- **Beheer (spec 4.9):** the action order on the Gebruikers cards, the 52 px avatars (square with
  the red ring for the admin), the amber pill, 12 swatches as a radio group with arrow keys, the
  logo panel, findings as cards, units, "Opslaan" top right and the CSV examples are all there.
  D29 is closed for the app background.

Security holds. Every user string I found going into `innerHTML` is escaped: names, ids, group
names, vak labels, exam titles in bar tooltips, finding messages and paths (`textContent`), and the
CSV example. The ring colour from a user file reaches the DOM only through `escHtml` and the CSSOM.
No inline `style=` or event attributes were added.

There are two majors. The new "Map openen" buttons cannot work in the real app, because the
backend only opens render outputs and printed PDFs; the mock accepts anything, so the e2e tests
pass (M1). And the student cards of years 4-6 make an `ensureYear` IPC call, which runs six
`create_dir_all` calls on the share, per student per school year, on every render of the list
(M2).

Process: the step 27 card numbers are still a STOP for the user (PLAN-2 step 27,
`step-27-card-numbers.md`). The fixture has no upper-school history, so the SE half of the cards
is checked only by unit tests.

## Majors

### M1. "Map openen" (Gegevenscontrole, Instellingen) always fails in the real app

- `ui/src/screens/gegevens.ts:273-276` passes `folderOf(issue.path)`, e.g.
  `2025-2026/scores/nat`, to `api.openPath`. `ui/src/screens/instellingen.ts:266-270` passes
  `snapshots`.
- The backend refuses both. `src-tauri/src/render.rs:310` calls
  `outputs::openable_path` (`crates/maatwerk-core/src/outputs.rs:139-152`), which accepts only a
  render output id or `rapporten/<schooljaar>/<file>.pdf`; anything else is
  `InvalidPath { reason: "only render outputs and printed PDFs can be opened" }`. A folder (and
  `''` for a finding at the top) never passes. The user sees "Map openen mislukt: only render
  outputs and printed PDFs can be opened", in English.
- The mock's `openPath` (`ui/src/bridge/mock/mock-api.ts:772-775`) records the call and returns
  `''`, so `beheer.spec.ts:75-79` and `:111` pass. The `api.ts:219-223` doc comment ("or a
  data-relative file") also promises more than the backend does.

Fix: add a separate core function and command, e.g. `openDataFolder(rel)`. It should accept only
a directory inside the data folder (through `maatwerk-core::paths`: no `..`, not absolute, no
symlink escape, `is_dir()`), with `''` meaning the data folder itself. Keep `openPath` for
outputs. Make the mock refuse what the real command refuses, add a core test for the allowlist,
and translate the error. Until then, hide the buttons.

### M2. Upper-school cards call `getStudentHistory` per student on every render: an `ensureYear` IPC per year per student

- `ui/src/screens/cards/student-grades.ts:73-79` awaits `Store.getStudentHistory(s.id, subject)`
  once per upper-school student, one after another. `ui/src/store.js:778-783` then calls
  `await loadYear(year, subject)` for every school year, and `loadYear` (`store.js:471-472`)
  always calls `window.maatwerk.ensureYear(year)`, without a cache. On the Rust side that is a
  `spawn_blocking` plus six `create_dir_all` calls on the shared folder
  (`crates/maatwerk-core/src/storage/mod.rs:565-577`).
- 300 students in years 4-6 with 4 school years means about 1,200 IPC round trips and about
  7,200 filesystem calls on a OneDrive/SMB share, one after another, before the last card has its
  numbers.
- `renderStudentList` starts all of this again on every search keystroke (`leerlingen.ts:90-93`),
  every filter change and every background refresh (`staged: false`). Each run first empties the
  grade slots (new card HTML; `html` is a fresh `Map`), so a colleague's save makes every card's
  numbers blank out and come back.
- `groepen.ts:250-257` does the same for upper-school groups (in parallel, so the IPC calls arrive
  as a burst).

Fix: in `student-grades.ts` (and `groepen.ts`), call `Store.loadYear` (or a new
`Store.ensureYearsLoaded`) once per year before the loop. Then build the history from the cache,
e.g. a `getStudentHistorySync` or a `getStudentHistory(..., { loaded: true })` that skips
`loadYear`. Also memoise the HTML per `(student id, year, record identity)` across renders, so a
keystroke or a background refresh re-uses the numbers it already has and recomputes only what
changed. A perf test (`perceived-speed.spec.ts`) with a few hundred upper-school students would
guard this.

## Minors

### m1. Login: Escape or "Andere gebruiker" works during the flight and during a pending login

`ui/src/screens/login/login.ts:221-222` focuses the PIN field and sets `busy = false` straight
after starting the 600 ms flight, without awaiting it. The `pin-panel.ts:53-56` comment says
focus comes "after the avatar's flight". Escape in the field (`pin-panel.ts:169-175`), or the
back button, which is clickable during the form's 200 ms delay (`fill: 'backwards'`, opacity 0),
runs `back()` mid-flight:

- `at = hero.getBoundingClientRect()` is the transformed, half-scaled box;
- the reverse starts from `transform: none`, so the hero jumps to the end spot;
- `flipTransform(to, at)` then scales relative to the wrong size, so the avatar lands off target
  before it snaps back.

`back()` is also allowed while `submit()` waits on `verifyPin`, `setFirstPin`, `initSubject` or
the recovery-codes dialog. It clears the form, and then `logIn` still navigates to Leerlingen as
that user. `forgot()` (`pin-panel.ts:90-98`) has no `try`, so a failing `finish` leaves an
unhandled rejection and a busy button.

Fix: keep `busy` true until the flight's `finished`, and only then call `panelApi.focus()`. Have
the panel ignore `onBack` while a submit runs (or disable the back button with `setBusy`), and
wrap `forgot()` like `submit()`. Add an e2e test that presses Escape right after the badge click.

### m2. Photo files: written before the record is saved, and never removed

- `ui/src/modals/gebruiker-edit.ts:243-245` writes `afbeeldingen/<id>.jpg` before
  `save(saved, user?._meta?.rev)` (`:275`). When that save fails with a rev conflict (for example
  because the teacher just changed their own photo through "Foto wijzigen"), the admin is told
  "Niet opgeslagen", but the teacher's photo file has already been overwritten by the admin's. With
  D28 both write the same file name, so this is now the normal case, not an edge case.
- Removing a photo ("Verwijderen" in either dialog; `foto-wijzigen.ts:66-71`,
  `gebruiker-edit.ts:246-247`) only clears `foto` in the user file. The image stays in the shared
  `afbeeldingen/` folder. A teacher who removes their photo will expect it to be gone (privacy).
  An older `.png` also stays when a new `.jpg` is saved (STATE notes this).

Fix: save the record first (with the rev check) and the photo after it, or write the photo to a
temporary name and rename it once the record is in. Delete the old file after a successful
"remove" or rename (this needs a core `deletePhoto` limited to `afbeeldingen/`).

### m3. The SE average can use only this year's tests on the first visit

`ui/src/screens/cards/student-grades.ts:72` takes `Store.getAllExamsSync(subject)` before the loop.
At that point only the active year's exams are in the cache (`initSubject` loads one year;
`store.js:492-502`). The other years are loaded later, inside `getStudentHistory` (`:78`). So
`se_average` (`crates/maatwerk-grades/src/averages.rs:37-53`) does not find an earlier year's
parent of a resit and falls back to the resit's own `type` and `weging_se`. Resits copy their
parent at creation (`herkansing.ts:143-150`), so the numbers usually agree, but not when the
parent's PTA/weging was edited later. The first render and every later one would then differ.
`groepen.ts:249` vs `:254` has the same order. `groep-leerlingen.js:62-63` has the right order.

Fix: load the years first (see M2), then take `getAllExamsSync`.

### m4. The group card fill is not cancelled when the list is drawn again

`ui/src/screens/groepen.ts:229-233` starts `fillGroupGradeStats` with no handle. A filter or year
change during a slow fill (M2) leaves two fills writing into `#group-list`. The older one can
overwrite a card of the new render with numbers computed for the old filter state. For the same
year these are the same numbers, but on a background refresh they come from records that are
older now. `student-grades.ts` has `cancel()`; the group screen should do the same (a render token
checked before each `innerHTML`).

### m5. "Nog geen cijfers" hides an SE average that exists

`ui/src/screens/cards/card-html.ts:51` returns "Nog geen cijfers" whenever the year average is
null. For a year 5 or 6 student at the start of the year (no tests yet this year, but PTA grades
from year 4), the card hides an SE average that the profile shows. It also does so when only
diagnostic grades exist, even though their bars are known. Spec 4.3 says "No grades yet". Show
`SE X,X` when `se !== null`, and the bars when there are any; keep "Nog geen cijfers" for no
grades at all. This is a card-number choice for the user's STOP in any case.

### m6. The snapshot keep rule is duplicated in TypeScript

`ui/src/screens/instellingen.ts:82-141` (`snapshotKinds`, `isoWeek`) re-implements
`maatwerk-core::snapshots::keep` (`snapshots.rs:193-231`) with its own date parsing (`new Date` in
local time, while Rust uses `PrimitiveDateTime`) and ISO-week code. It is display-only, but it is
the same rule in two places and can drift. CLAUDE.md layering puts logic in core. Fix: have
`listSnapshots` (or a new command) return the kind per name from `keep`, and drop the TS copy and
its test.

### m7. Parity gaps with board 12 and D29

- The finding actions "Vergelijken" (OneDrive conflict copy) and "Toets openen" (broken reference)
  of spec 4.9 are missing. Every finding gets only "Map openen", which itself does not work (M1).
  STATE says so; it should go to the backlog explicitly.
- D29 is marked closed in `quirks.md`, but the rapport still reads only
  `afbeeldingen/school-watermerk.svg` (`crates/maatwerk-core/src/typst_svc/rapport.rs:42`), so a
  legacy PNG watermark shows in the app but not on the rapport. Either narrow the closing note to
  "app background" or let the rapport read `school.watermerk` too (the upload now accepts SVG only,
  so this only affects older folders).
- X-06 (`rapporten/` retention) is not in the step (no decision). This is documented.

### m8. Test gaps

- Nothing ties the UI's `openPath` targets to the backend allowlist (M1). A `tauri-api.test.ts` or
  core test with a folder target would have failed.
- `csv-example.test.ts:17-27` checks only the headers of the group and assignment examples. The
  import's own checks (`groep-edit.js:553-604`: Schoolsoort, `VAKKEN_MAP`, Leerjaar) are inline and
  never run on the example. A row the import skips would ship unnoticed. Move the row parsing into
  `domain/groups.ts` and test the example through it.
- No test of `fillStudentGrades` (cancel on re-render, `show` for cards added in idle slices, the
  upper-school path) and no e2e test of Escape during the flight (m1).
- `folderOf` and `checkedLine` are tested in `instellingen.test.ts:81-90`, though they live in
  `gegevens.ts`.

## Nits

### n1. Two more private HTML escapers

`ui/src/screens/cards/card-html.ts:17-23` and `ui/src/utils/csv-example.ts:37-39` each define an
`esc` next to `escHtml` in `app.js`. The csv one does not escape quotes (it is used only in text,
so it is safe today). Move one shared `escHtml` into `utils/` (which also removes the app.js
import from TS modules).

### n2. Focus on the login start stage

No element has focus when the login screen opens (`login.ts:127-308`). Without a remembered vak,
a keyboard user must Tab from the document start. Focus the first enabled tile, or the
remembered vak's first user.

### n3. Photo crop details

`photo-crop.ts:181`: a horizontal wheel or trackpad swipe (`deltaY === 0`) zooms out. Ignore
`deltaY === 0`. `photo-crop.ts:70`: `aria-label` on a `div` without a role is ignored by most
screen readers.

### n4. `cacheUser` twice after "Foto wijzigen"

`Store.saveOwnPhoto` already calls `cacheUser(saved)` (`store.js:332`). The `onUserChanged(saved)`
in `app.js` (`onChangePhoto`) does it again.

### n5. `applyWatermerk` keeps the old background when the new file cannot be read

`ui/src/app.js:624-629` sets `--watermerk-url` only when `dataUrl` is truthy. If the new file is
missing or unreadable, the previous watermark stays until restart. The promise is also
fire-and-forget at both call sites (`app.js:818`, `school.js:292`), so a refused path ends as an
unhandled rejection. Remove the property when `dataUrl` is null, and catch the error.

### n6. More circular imports with `app.js`

`screens/login/login.ts:11` and `screens/school.js:3` (`applyWatermerk`) import from `app.js`,
which imports them. They work because the bindings are used only at call time. This follows the
existing pattern, but `applyWatermerk` could live in `shell/` to break one cycle. `school.js`
stays JS (R-05), as STATE notes.

### n7. `api.ts` doc for `openPath`

`ui/src/bridge/api.ts:219-223` says "a render output or a data-relative file". The backend allows
only outputs and printed PDFs. Fix the comment along with M1.

- **M1 fixed:** a new core function `outputs::openable_folder` (existing folders inside the data
  folder only, path-checked by `DataDir::resolve`; tested) and command `open_data_folder`
  (bridge `openDataFolder`); Gegevenscontrole and Instellingen use it. The mock refuses `..` and
  absolute paths as the core does. n7 (the `openPath` comment) fixed with it.

  (`Store.loadYear` + `preloadScores`), and `getStudentHistory(id, vak, { loaded: true })` skips
  the per-student reload. Computed card numbers are kept per `Store.generation()`, so a search or
  a filter change shows them at once (e2e "a search keeps the numbers on the cards": no new
  reads). m3 (years loaded before `getAllExamsSync`) and m4 (an older group fill stops) fixed with
  it.
- **m1 fixed:** "Andere gebruiker" and Escape wait until the avatar has landed and are ignored
  while a PIN is checked or the session starts.
- **m5 fixed:** a card without a grade this year but with an SE shows "SE X,X".
- **Not fixed, in `docs/backlog.md` "From Steps 26-28":** m2, m6, m7, m8 and the nits.
