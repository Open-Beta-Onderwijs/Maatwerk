Scope: `git diff 87ad870..HEAD` on `step/35-rights` (score lock, Sectiesecretaris, session
roles, start on the vak tiles; Gastaccount, read-only gast session, Kopieer naar…). Checked
against PLAN-2 decisions 78-82 and steps 35/36, ADR-0006 "Roles and rights", data-files-v3
(0.26 / 0.27 sections), STATE and CLAUDE.md. Cargo was not run (gate already ran).

## Blockers

## Majors

**M1. A user's untracked file was committed and breaks `npm run lint` on CI.**
`docs/reviews/manual-test-step-32.md` (460 lines) went in with `69115b5` (feat(core): gast
session...). STATE still calls it "the user's untracked" file, and the gate's lint failed only on
it. Once it is tracked, root `prettier --check .` fails on it (confirmed:
`npx prettier --check docs/reviews/manual-test-step-32.md` warns), so CI goes red and `main`
would not be green after the merge. Fix: `git rm --cached docs/reviews/manual-test-step-32.md`
in a new commit (the file stays on disk for the user), or ask the user whether to format and keep
it.

**M2. The gast login does not wait for the previous user's backend logout, so the gast guard can
be lifted.** `ui/src/screens/login/login.ts:194-195` awaits `scoreSavesDone()` and then calls
`loginGast(vak)`. It does not await `backendLogoutDone()`, which the PIN path does
(`pin-panel.ts:158`, and the comment there says why). `logoutAfterSaves` (`session.ts:132`)
chains `api.logout()` on the same `saveChain`. When saves are queued (slow OneDrive) and the next
person clicks Gast, two `spawn_blocking` jobs, `logout` and `login_gast`, are in flight and can
run in either order. If `logout_from` runs last, it clears the session and calls
`set_guest(false)`. The UI then shows a gast while the core holds no session and no guest flag:
writes outside the score files go through (and score writes fail with "Niet ingelogd."). Fix:
`await backendLogoutDone()` before `loginGast`. Better still, make `logout_from` clear only the
session it was asked to end (for example, pass the expected user id), so that no login can be
undone by a late logout. Add a unit test with a slow save chain.

**M3. A gast can still open Observatie bewerken, and the "nothing writable" e2e cannot catch
it.** The Observatie card title is `<button data-action="edit-obs">` with no `data-write`
(`ui/src/screens/observaties/card.ts:83`). Its handler (`ui/src/screens/observaties.ts:81`)
calls `openObsModal` before the new `isGast()` check on line 87, which covers only the
card-body click. The gast gets the full edit dialog with Opslaan and Verwijderen. The core refuses
the save, so no data is lost, but step 36 item 3 says every edit control is hidden or disabled.
The sweep in `ui/e2e/gast.spec.ts:69` only asserts `[data-write]:visible` count 0. That holds by
construction, because CSS hides every `[data-write]`, so the test passes for any control that
lacks the mark. Fix: return early for a gast in the `edit-obs` branch (or render the title as
plain text for a gast). Make the sweep behavioural: on each tab, click every card title and button
that is not `data-write`, and assert that no dialog with a primary save or delete button opens.
Alternatively, assert that `writeJson` / `deleteFile` were never recorded by the mock.

## Minors

**m1. A gast still creates folders in the data folder.** `Store.loadYear` calls
`ensureYear(year)` on every year load (`ui/src/store.js:496`). `ensure_year` / `ensure_dir`
(`storage/mod.rs:614-635`) call `fs::create_dir_all` without `check_writable`, so a gast who
opens a school year that has no folder yet creates `<year>/exams`, `groups` and
`scores/<vak>` on the shared folder. Decision 81 says the gast "never writes, creates or
deletes". The classification test lists both under `NO_DATA_WRITE` (`src-tauri/src/lib.rs:436-437`).
Fix: `refuse_guest()` (or skip creation) in `ensure_dir`, or skip `ensureYear` in the UI for a
gast (and for a read-only app), and move both to `STORAGE_WRITE`.

**m2. The classification test does not check behaviour, and some labels are wrong.** Step 36
item 2 asks for "a Rust test [that] walks the command list and checks each writing command
refuses a gast". `every_command_is_classified_for_the_gast_guard` (`lib.rs:363`) only checks
that each command name is in exactly one list. Several commands that write the data folder through
`Storage` sit in `NO_DATA_WRITE`: `set_first_pin`, `change_pin`, `recover_with_code`,
`renew_recovery_codes` (user file) and `project_files_status` (updates project files and
already handles `GuestReadOnly`). They are safe only because `Storage` guards them. Fix: move
them to `STORAGE_WRITE`. For the storage-level guard, keep the core test
`a_gast_writes_nothing_but_presence` as the behavioural proof, and add `ensure_dir` / `delete`
/ `remove_empty_dir` cases there.

**m3. The PO move rule lets any teacher wipe a foreign student's PO grading.**
`rights.rs:396-401`: when the student's file names another projectgroep than the exam (or none),
an empty `group_grading(new)` is accepted, whatever else changed. This happens, for example, when
the student has PO scores but no `po.projectgroep` (the validate-data case of step 37), or when an
earlier move did not follow. In that case a teacher who teaches no member can delete the
student's category scores, observaties and comments. Decision 79 says only the student's own
teacher may do that. Fix: accept the empty case only when `old` also has no group grading, or
when `pg(new) == group_id` and the empty result matches a staying member's empty grading. Add
a test.

**m4. The core compares raw member files with what the UI normalises, so legitimate saves can be
refused part-way.**
(a) `takeNewGroupGrading` writes `gradingOf(source)` (`linesOf` turns string values into
numbers, adds a missing `label`, and drops unknown `po` keys), but `exam_change_allowed`
compares it with the staying member's raw `group_grading`. Any such difference refuses the
move, and the persistentError then tells the teacher to "sla opnieuw op", which fails again.
(b) In `po-beoordelen` save (`po-beoordelen.ts:514-528`) members are written one by one. A
refusal on member k (for example, `writeGrading` deletes the whole `po` entry, including raw
`ownLines` of a locked member, when they parse to no lines) leaves members before k written. That
breaks the "same grading in every member file" invariant (decision 19).
Fix: in the rule, normalise both sides the same way (compare the parsed grading, as
`gradingKey` does). In the UI, run `teacherMayWrite` for every member before the first write and
stop with one message.

**m5. Every score write now reads the user file, school.json, every group file of the year and
the exam.** `check_json_write` (`rights.rs:221-228`) does this before each cell save, and for
each member of a PO save. On a OneDrive folder this is one directory walk per keystroke-save,
on the path step 33b just made fast. Fix: measure it with the step 33b perf spans. If it shows,
cache `YearGroups` per (year, vak, user), invalidated by the watcher, as other caches are.

**m6. The rights check and the write are not one step.** `write_json` (`commands.rs:88-90`) reads
the old file in `check_json_write`, then writes with the caller's `expect`. With
`Expect::Any`, the checked diff may not be the diff actually written (a colleague's change in
between is overwritten unchecked). Also, an unreadable old file becomes `Null`, so a delete of an
unparsable foreign score file passes (`changed` is empty). Fix: let the check return the hash it
read and write with `Expect::Hash(that)` when the caller passed `Any`. For a delete, fail closed
on a read error.

**m7. Kopieer naar writes the images before `opdracht.json`.** `copy_to_sectie.rs:105-108`:
`opdracht_images::copy` writes with `Expect::Any`, and only then does `opdracht.json` use
`Expect::Missing`. On an id collision (same millisecond, another PC) the images overwrite
another opdracht's files and then the JSON write fails. On any failure after the copy, an orphan
folder is left. Fix: write `opdracht.json` with `Missing` first (it claims the id), then the
images. On an error, delete the new folder.

## Nits

- n1. `ui/e2e/rights.spec.ts:87` says "Typing, Delete and a paste", but there is no paste and no
  cut. Add a Ctrl+V on a locked row (and an undo after a refused-but-typed cell, if reachable).
- n2. `is_presence` (`storage/mod.rs:163`) lets a gast write any file under `aanwezigheid/`,
  including other users' presence. Limit it to `aanwezigheid/<session id>.json`.
- n3. `Storage::as_teacher` resets the flag to `false` instead of restoring the previous value
  (`storage/mod.rs:248`). Harmless today (it is never nested); restore the old value anyway.
- n4. Rust and TS differ in small ways. Rust compares `serde_json::Value` numbers, so `1` vs
  `1.0` counts as a change, but in TS it does not. TS `obs_ids` / `projectgroep` are compared
  without `String()`, but Rust's `str_list` accepts numbers. The mock's `aanwezigheid/` and
  `bestuur:<vak>` checks are case-sensitive, but the core's are not. Either share a small
  table of cases between `rights/tests.rs` and `rights.test.ts`, or normalise the same way.
- n5. The core accepts Kopieer naar into the gast's own vak (the UI excludes it). Check
  `vak != gast vak` in `copy_opdracht_to_sectie` too.
- n6. STATE says the version "stays 0.26.0" for step 36. data-files-v3 names the Gastaccount
  "0.27". Settle this at the release question.

## Verified OK

- Core never depends on tauri. Command handlers stay thin (parse role, call core, map errors).
  SPDX headers are on all new sources.
- `Role::parse` / `as_string`. `verify_pin_as` refuses a role only after a correct PIN.
  `change_pin` / `renew_recovery_codes` use `check_pin`, so the role is kept. `login()` sets
  or clears the guest flag. `logout_from` clears it.
- `effective_role` re-checks school.json and the user file at every guarded write (7b n4).
  Bestuur falls back to docent, and a deactivated user gets no rights.
- The score-lock core rule matches the TS mirror on key order, absent vs `null` vs `[]` own
  lines, and number vs string student ids. The exam-edit sweeps (`removeObsFromExamScores`
  after `upsertExam`, `removeStudentExamData` for leavers) pass the rule because the exam is
  written first.
- Score grid: typing, paste, cut, Delete, F-keys, 0/1 on observaties, override context menu,
  and `isEditable` all skip locked rows. The roster signature includes `docenten`.
- PO beoordelen: read-only without an own member. Locked own lines are disabled, and their raw
  `ownLines` are kept on save.
- The gast guard is in `Storage::commit_bytes` / `delete` / `remove_empty_dir`. `print_copy`
  refuses (preview only, as the user answered), and `printOutput` opens the PDF instead.
  `ai_send` refuses. Preferences are not saved (`isReadOnly()` includes guest). Migration
  cannot run with a session.
- Kopieer naar: gast-only, target teacher active / not admin / teaching the vak. The PIN is
  throttled on the login key `pin:<id>`. `vakken` is the target, `observaties` is emptied, and
  `_meta.createdBy` is the teacher. `as_teacher` is thread-local and limited to the one
  `spawn_blocking` closure.
- Start screen: the last vak is highlighted and focused, not chosen (user's addition).
- Gebruikers: the secretaris dropdown leaves out the voorzitter, and one person holds one role.
  The Gastaccount checkbox writes `secties.<vak>.gast` through `updateSchool`.
