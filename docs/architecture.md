# Architecture (short)

The decisions and their reasons are in `docs/adr/` (ADR-0002 is the main one). This page is the
map.

```
ui/  (Vite, JS + TypeScript)  ->  bridge (window.maatwerk)  ->  Tauri IPC
  -> src-tauri/ (commands: parse args, call core, map errors)  ->  crates/maatwerk-core/
crates/maatwerk-cli/  (headless tools on the same core)
```

## Crates

- **`maatwerk-core`** (no Tauri, CI checks it): `paths` (`RelPath`, `DataDir`: every path from
  the UI is checked against `..`, absolute paths and symlink/junction escapes), `storage`
  (atomic writes, CAS by content hash, `_meta` stamps), `watcher` (OS notifications plus a poll
  of the active year; own writes suppressed; restarts after a panic), `migrate` and `validate`
  (data format v2, Gegevenscontrole), `auth` (PINs, Argon2id), `snapshots` (zip snapshots in the
  shared folder), `presence`, `typst_svc` (Typst as a library: sandboxed World, rapport and
  opdracht PDFs, batch, live editor session, IDE queries), `pdf_merge`, `outputs`,
  `opdracht_images`, `assignment` (headless opdracht check/render), `assets` (embedded
  templates, fonts, Typst packages).
- **`maatwerk-cli`**: `validate-data`, `migrate`, `admin reset-pin`, `typst compile`,
  `assignment check | render | export-lib`.
- **`src-tauri`** (`maatwerk-app`, binary `maatwerk`): commands in `commands.rs`, `data.rs`,
  `auth.rs`, `opdrachten.rs`, `render.rs`, `editor.rs`, `problems.rs`; shared state in
  `state.rs` (the core is opened on a background thread; commands wait for it on their blocking
  thread); the `maatwerk-out` URI scheme serves render outputs; `start_error.rs` shows a Dutch box
  when the app cannot start.

## UI

`ui/src/bridge` holds the typed bridge: `bindings.ts` is generated by tauri-specta
(`npm run bindings`), `tauri-api.ts` maps it to the reference's result shapes (compat layer,
removed screen by screen in phase 2), `mock/` is an in-memory backend for e2e tests and the mock
build. `domain/` is pure TypeScript (grades, RTTI, ids, v2 codec) with unit tests; `screens/`,
`modals/`, `components/` are the screens (legacy JS migrating to TS). The Typst editor runs in an
iframe (`editor.html`) on a core live session.

## Data

One shared `data/` folder (OneDrive) per school, JSON files, format v2
(`docs/reference/data-files-v2.md`). Every write is a CAS on the file's hash; a colleague's
change in between is a conflict, never a silent overwrite. Printed PDFs go to `rapporten/` next
to `data/`; render outputs to the local cache; logs to
`%LOCALAPPDATA%\nl.openbetaonderwijs.maatwerk\logs` (14 days, no student data).

## Threads

Heavy work (file I/O, Typst, merge, directory walks) runs in `spawn_blocking`; long-lived
threads: the watcher, the editor compile thread with a watchdog, the snapshot job at start.
Panics in a blocking task become an `internal` error; in the watcher it restarts; in a batch job
it is that job's error; all are logged.

## Tests

`docs/testing.md`: Rust unit and golden tests (Typst output pixel-compared with the old app),
Vitest for the UI domain and bridge, Playwright e2e on the mock build, manual checks in
`docs/manual-test.md`.
