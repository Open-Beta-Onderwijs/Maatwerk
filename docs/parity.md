# Parity table

One row per reference IPC handler and per UI-visible behaviour: where it lives in the port and
which test pins it (PLAN.md 2.2). Started in Step 3a; Steps 4-6 fill in the Rust commands.

Status: **mock** = implemented by `MockApi` only (UI runs on it; real backend in Steps 4-6);
**core (4a)** = implemented and tested in `maatwerk-core` only; **port (4b)** = Tauri command
(generated binding) and `TauriApi` compat mapping (`ui/src/bridge/tauri-api.test.ts`);
**port** = ported and tested; **fixed** = ported with a decided fix (quirk id); **dropped** = not
ported (reason given); **todo** = later step.

Test locations: Vitest `ui/tests/**`, `ui/src/**/*.test.ts`; Playwright `ui/e2e/**`; logic goldens
`tests/golden/logic/*.json` (reference behaviour, Step 2).

## Typst goldens (`tests/golden/typst/`, `docs/reference/typst-contract.md`)

Rust tests in `crates/maatwerk-core/tests/typst_rapport.rs` and `typst_opdracht.rs` compile the
golden's call arguments with `typst_svc` and compare page count, page sizes, text (without
whitespace and soft hyphens) and every pixel of the 30 ppi PNGs (`tests/support/mod.rs`). Pixels
may differ by up to 3 levels per channel: only JPEG photos do (`opdracht-images-student`), because
our `image` crate decodes with a newer zune-jpeg than the reference CLI's build. Emoji are Noto
Color Emoji on both sides: the harness adds Maatwerk's bundled font to the reference's
`include/fonts` and renders the PNGs with `--ignore-system-fonts`, and the tests compile without
system fonts (`support::fonts`), so no golden depends on the machine (quirk T2). Opdracht inputs
are the tiny fixture's `opdrachten/` (`crates/maatwerk-core/tests/fixtures`, kept in sync by
`tools/fixtures/export-opdrachten.mjs`); a v1 opdracht compiles as a virtual project with the
bundled `main.typ` (data via `sys.inputs`) and the cursor marker renamed (naming map). Batch
goldens compare the merged PDF's text with lopdf, without emoji (lopdf cannot extract Typst's
colour emoji glyphs; pdf.js reads the merged `batch-duplex` PDF identically, checked by hand). Data reaches the template as JSON (`data.json`), and the UI passes it
through `normaliseForTypst` first, which restores the `toTypst` values (`undefined` -> `none`,
non-finite -> `0`; review 5a M1).
